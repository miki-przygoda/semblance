# CI, with every flyvis gate live

**Date:** 2026-10-01
**Status:** approved, not yet implemented
**Epic:** 0.2.0 flyvis import — the "close the CI gap" item, the last open
ruling before the bump (`docs/project-outline/0.2.0-flyvis-import/README.md`)
**Prior notes:** `docs/project-outline/chore-and-fixes/README.md`, "Acceptance
tests skip silently without the flyvis data"

## Why

The gates that prove this workspace reproduces flyvis — the 1,513,231-edge
expansion, the bit-exact flash and dot fixtures, the moving-edge tolerance gate —
read gitignored data. Without it they early-return and pass, and libtest hides
the skip notice. So far they have only ever run on one machine.

`SEMBLANCE_REQUIRE_FIXTURES=1` already turns a missing fixture into a failure.
What is missing is somewhere that sets it, with the fixtures present. That is
this spec.

**What CI must guarantee:** every gate, including the flyvis ones, on every pull
request and every push to `main`.

## What was decided, and the alternatives it closed

**Hosted, pinned fixtures (chosen).** The flyvis-produced fixtures are uploaded
once to a private release and verified by committed checksums on every run.

**Regenerate in CI (rejected for per-PR use).** Installing Python, flyvis and
PyTorch and re-running `tools/` on every push gives the strongest provenance, but
it is slow, expensive on a private repo's metered minutes, and fails whenever
upstream does. It stays available later as an occasional drift check. It is not
part of this spec.

**Data-free checks only (rejected).** Cheap, but it ships the exact gap the
chore note warned about: the gates that matter most never run anywhere except a
developer's machine.

## Facts this design rests on

Measured on 2026-10-01, not assumed:

| fact | value |
|---|---|
| repo visibility | private |
| full suite, debug, `SEMBLANCE_REQUIRE_FIXTURES=1` | ~1.4 s |
| data the tests read | `data/flyvis-supplementary/Lappalainen_et_al_connectome_avg_filters.json`, all of `data/flyvis-build/`, all of `data/flyvis-stimuli/` |
| data no test reads | `data/flyvis-pretrained/` — trained parameters are compiled into `pretrained.rs` |
| `data/flyvis-build/` + `data/flyvis-stimuli/` | ~49 MB, 19 files |
| connectome JSON, sha256 | `e609438ef261f4d12bf12556f4edb7a898ca4720029f9b882868967e6a0bbc73` (188 KB) |
| flyvis's `fib25-fib19_v2.2.json`, sha256 | `bfbb0766251ff09e22723d0ebbf7b14793e70b3ae8ad0eea64eac9d28223351a` (618 KB) |
| Springer supplementary zip | reachable, HTTP 200 |
| local toolchain | rustc 1.97.1 |

**The two connectome JSONs are not byte-identical.** The 2026-09-20 audit found
them *deep-equal*: the same content, formatted differently. So CI cannot
substitute flyvis's GitHub copy for ours under our filename. It fetches the
published zip instead.

## Design

### 1. Fixture sources, both pinned

**The connectome JSON comes from the publication.** The fetch script downloads
the Springer supplementary zip (the URL in `RESOURCES.md`), extracts only
`Lappalainen_et_al_connectome_avg_filters.json` into `data/flyvis-supplementary/`,
and verifies its sha256. Fetching from the original source is stronger provenance
than hosting our own copy of someone else's file. In CI, the extracted JSON is
cached by that hash, so the 57 MB zip is rarely fetched.

**The flyvis exports come from a private release.** `data/flyvis-build/` and
`data/flyvis-stimuli/` are packed, with their `PROVENANCE.json` and
`moving_edges_provenance.json` intact, into one tarball. The tarball is
attached to a GitHub release under the tag `fixtures-1`. The tag is
deliberately outside the `vX.Y.Z` scheme, so it is never mistaken for a
version.

### 2. Committed files under `ci/`

| file | contents |
|---|---|
| `ci/fixtures.sha256` | one line per fixture file, in `shasum -a 256 -c` format: the connectome JSON plus every file in the two export directories |
| `ci/fixtures-tag` | the release tag to download, currently `fixtures-1` |
| `ci/fetch-fixtures.sh` | fetch-and-verify; run by CI and usable locally |

Checking file by file means a corrupted or stale bundle fails with the name of
the file at fault, and the checksum file is itself the list of the fixture set.

**Re-exporting fixtures** means uploading a new tag (`fixtures-2`) and updating
`ci/fixtures-tag` and `ci/fixtures.sha256` in one commit, so the change is
visible in review.

### 3. `ci/fetch-fixtures.sh`

POSIX-ish bash; needs `curl`, `unzip`, `tar`, `shasum` and `gh`, all present
on `ubuntu-latest` and on a typical macOS dev machine.

1. If every file listed in `ci/fixtures.sha256` exists and verifies, exit 0 and
   download nothing.
2. If any listed file **exists but fails verification**, exit non-zero naming
   it, and **do not overwrite it**. Locally that file may be a deliberate
   re-export; clobbering it would destroy the evidence. CI starts clean, so this
   only bites locally, which is where it should.
3. Otherwise, fetch only the sources that are missing: the Springer zip for the
   JSON, and `gh release download "$(cat ci/fixtures-tag)"` for the tarball.
   Extract, then verify everything against `ci/fixtures.sha256`, and exit
   non-zero on any mismatch.
4. Temporary downloads go in a `mktemp -d` directory, removed on exit.

The script lives outside the workspace and nothing in Rust references it, the
same boundary `tools/` holds. `Cargo.lock` keeps exactly 8 packages.

A side effect worth stating: a fresh clone can now run every flyvis gate with
`gh` access alone, without installing Python, flyvis or PyTorch.

### 4. `.github/workflows/ci.yml`

Triggers: `pull_request`, and `push` to `main`. Runner: `ubuntu-latest`.
Permissions: `contents: read`. Actions used: only `actions/checkout` and
`actions/cache`. Rust comes from the runner's preinstalled `rustup`, not a
third-party action.

**Job `test`, Rust 1.97, pinned:**

1. Check out; `rustup toolchain install 1.97 --profile minimal -c clippy`.
2. Restore the cargo cache (`~/.cargo/registry`, `~/.cargo/git`, `target/`),
   keyed on toolchain + `Cargo.lock`. Restore the connectome-JSON cache, keyed
   on its sha256.
3. `ci/fetch-fixtures.sh`, with `GH_TOKEN: ${{ github.token }}`.
4. `cargo build --workspace`
5. `SEMBLANCE_REQUIRE_FIXTURES=1 cargo test --workspace`
6. `SEMBLANCE_REQUIRE_FIXTURES=1 cargo test -p semblance-flyvis
   moving_edge_offsets_match_flyvis_within_tolerance -- --nocapture`. This
   reruns the geometry gate so its distribution table is in the log. The
   gate exists to be read, not just passed, and a table in the log is
   evidence that it actually ran.
7. `cargo clippy --workspace --all-targets -- -D warnings`
8. `cargo run --quiet -- roundtrip`, then fail unless the output contains both
   `structural distance:  0.000000` and `behavioural distance: 0.000000`,
   matched as literal strings. Lossless means exactly zero, not within a
   tolerance.

**Job `msrv`, Rust 1.85:** `cargo build --workspace --all-targets`. The
workspace declares `rust-version = "1.85"` and nothing has ever checked it. This
job compiles only: no fixtures, no tests, no clippy, so new lints never reach it.

**Why the `test` job pins 1.97 rather than tracking stable:** with
`-D warnings`, a lint added in a new stable release would turn CI red with no
change in the repo. Pinning makes a toolchain bump a deliberate one-line change
that brings any new lints into review. The pin lives only in the workflow; no
`rust-toolchain.toml` is added, so local builds are unaffected.

**Expected cost:** the tests themselves take ~1.4 s, so each run is mostly
compilation, roughly 2–4 minutes with a warm cache. The 49 MB tarball downloads
on every run. Caching it by tag is a small extension if that ever matters.

### 5. Clippy goes to zero

The five pre-existing warnings are resolved at their sites:

- **`crates/connectome/src/lib.rs:130`: fixed.**
  `split(|ch| ch == ',' || ch == '\t' || ch == ' ')` becomes
  `split([',', '\t', ' '])`. Same behaviour; `connectome` is staying.
- **`crates/sim/src/lib.rs`, four `needless_range_loop` sites (lines 72, 168,
  178, 234): silenced, not fixed.** Each gets a scoped
  `#[allow(clippy::needless_range_loop)]` on its enclosing function, with a
  one-line reason saying `sim` is due to be replaced in 0.4.0. Rewriting
  those loops would be the investment in `sim` that `CLAUDE.md` rules out. The
  allows disappear along with the code.

`CLAUDE.md`'s "Clippy currently has 5 pre-existing warnings" becomes "clippy is
clean, and CI enforces it with `-D warnings`". Its "Verifying a change" section
gains a pointer to `ci/fetch-fixtures.sh`.

## Deliberately out of scope

- **`cargo fmt --check`.** The repo is not rustfmt-clean. `chore-and-fixes`
  records that formatting is its own deliberate change, not something to bundle
  into another branch.
- **macOS / Windows runners.** The one platform-specific risk on record, `gaussian()`'s
  dependence on the host libm, is already documented. Extra OSes multiply metered
  minutes for no identified need.
- **Scheduled regeneration from flyvis** (the rejected per-PR option, kept as a
  possible later drift check).
- **Sintel.** Deferred, unscheduled, 2026-10-01. See the epic README.

## One step that needs explicit sign-off

Creating the `fixtures-1` release and uploading the tarball publishes data to
GitHub. It is private to the repo, but it is still outward-facing. The
implementation pauses for confirmation before doing it.

## Done when

- A pull request runs both jobs green, and the `test` job's log shows the
  fixture gates executing, not skipping. Concretely, the moving-edge gate's
  distribution table, from step 6, appears in the output and matches the
  local figures (0.000794 / 0.002823 / 0.002692 / 0.003057).
- **A deliberate break is caught.** On a throwaway branch, corrupting one
  fixture byte fails `fetch-fixtures.sh` with that file named. Removing a
  fixture from the bundle fails the test step. Neither change is merged.
- `cargo clippy --workspace --all-targets -- -D warnings` passes locally.
- `Cargo.lock` still lists exactly 8 packages.
- The 0.2.0 epic README records the CI gap as **closed**, and every 0.2.0
  task is then complete or explicitly deferred. Bumping is a separate decision.
